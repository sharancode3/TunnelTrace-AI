# RFC 8221
## Cryptographic Algorithm Implementation Requirements and Usage Guidance for Encapsulating Security Payload (ESP) and Authentication Header (AH)

**Authority:** Internet Engineering Task Force (IETF)  
**Publication Date:** October 2017  
**Status:** APPROVED / ACTIVE / PROPOSED STANDARD  
**Document Code:** RFC 8221  
**URL:** https://datatracker.ietf.org/doc/html/rfc8221  

---

### Section 3 ESP Encryption and Authenticated Encryption Algorithms
RFC 8221 provides explicit implementation status requirements for ESP encryption algorithms:
- `ENCR_AES_GCM_16` (AES with 128-bit or 256-bit keys in Galois/Counter Mode with 16-octet ICV): MUST be supported. AES-GCM is an Authenticated Encryption with Associated Data (AEAD) cipher and provides high performance and proven cryptographic security.
- `ENCR_AES_CBC` (AES in Cipher Block Chaining Mode with 128-bit or 256-bit keys): MUST be supported for legacy backward compatibility, but SHOULD NOT be selected when AEAD ciphers are available.
- `ENCR_CHACHA20_POLY1305` (ChaCha20 stream cipher with Poly1305 authenticator): SHOULD be supported as a modern alternative to AES on platforms lacking dedicated hardware AES acceleration instructions.
- `ENCR_3DES_CBC` (Triple-DES in CBC mode): MUST NOT be used. 3DES is officially deprecated due to vulnerability to birthday collision attacks (Sweet32).
- `ENCR_NULL` (ESP NULL Encryption): MUST NOT be used when data confidentiality is required. While ENCR_NULL may be configured in specialized debugging scenarios or when ESP is used purely for data integrity, it leaves all encapsulated user payloads exposed as cleartext across intermediate transit networks.

### Section 4 ESP and AH Integrity Algorithms
For implementations using non-AEAD ciphers (e.g., AES-CBC):
- `AUTH_HMAC_SHA2_256_128` (HMAC-SHA-256 truncated to 128 bits): MUST be supported.
- `AUTH_HMAC_SHA2_512_256` (HMAC-SHA-512 truncated to 256 bits): SHOULD be supported.
- `AUTH_HMAC_MD5_96` (HMAC-MD5 truncated to 96 bits): MUST NOT be used due to collision attacks on MD5.
- `AUTH_HMAC_SHA1_96` (HMAC-SHA-1 truncated to 96 bits): MUST NOT be used due to theoretical and practical collision vulnerabilities.
